# 刷卡异常回归

在仓库根目录执行：

```powershell
./apps/pos-wpf/scripts/Test-CardPaymentRegression.ps1
```

脚本先构建，再顺序运行三个互不重叠的分组，默认全部执行：

| 分组 | 用途 |
| --- | --- |
| `Correctness` | 支付、持久化、恢复、幂等、取消、导航和实际 WPF 恢复入口 |
| `Timing` | 必须经过真实时间才能验证的超时契约 |
| `Performance` | 搜索排队耗时、UI 心跳间隔等受机器负载影响的阈值 |

局部开发可指定 `-Suite Correctness`；完整验收运行默认 `All`，不能把单组通过称为全部回归通过。`-Configuration Debug` 可切换配置，`-ArtifactsPath` 可指定独立构建目录。不要与其他构建或性能测试并行运行。

每轮 TRX 和 `summary.json` 保存在产物目录下独立的 `test-results` 子目录。任一分组失败、零测试、跳过或缺失 TRX，脚本均返回失败。测试数量会随覆盖范围变化，不把固定数量作为质量目标。

新增关键测试应遵守以下约束：

- 跨层回归保留真实客户端、工作流和 ViewModel，只在终端、网络等外部边界使用替身；用类型化 fixture，不反射复用其他测试的私有实现。
- 取消、晚到响应和并发恢复通过显式信号安排先后次序。短延迟不能代替“请求已提交”或“取消已收到”的证据。
- 同时验证业务结果与资金副作用：原订单/交易身份、扣款提交次数、恢复只查询、不重复落单，以及异常处理入口和正确解锁。
- 静态 XAML 接线测试和真实 View 的运行时测试同时保留。运行时测试需检查按钮可见、可用及点击后的导航结果。

这些离线测试不代替真实终端断电、网络故障、银行结果核对和设备验收。
