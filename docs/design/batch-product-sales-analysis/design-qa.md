## 与设计图的明确差异

1. 实现保留 HB Web 既有导航、页签和页面标题，因此首屏信息密度低于没有页签的概念图；完整列表和全部日明细可向下滚动查看。
2. 商品列表先取聚合销量；只加载选中商品的每日及分店明细。首版没有为所有商品批量绘制行内迷你趋势，避免 500 个货号产生逐商品明细查询。
3. 折扣以实际成交及原单证据分类，图表显示折扣数量和价格提示。没有把折扣成交的连续日期标成已证实的促销活动时间段；未知记录单独展示。
4. 示例图中的分店占比与部分日数据并不完全守恒；实现使用可核对的示例数据，例如 86 / 268 = 32.1%，四店合计为 268。

## 实际交互证据

桌面使用 2026-09-01 至 2026-09-13：12 行输入去重 2 行，10 个有效货号，8 个匹配、1 个未匹配、1 个歧义，总销量 841。选中 001236 后，商品销量 268 = 正价 196 + 折扣 72；四个分店销量为 86、72、61、49，选中 Springfield 图表合计为 86。

窄屏最终截图使用 2026-09-01 至 2026-09-14，增加的 09-14 为零交易日，商品合计不变。浏览器观测 document.scrollWidth = clientWidth = 375，图表数量为 2，页面错误记录为空。

验收过程中切换浏览器视口曾观察到页面重新挂载；既有 AdminLayout 会在手机和桌面布局间更换页面容器。固定视口后重新执行查询、连续截图并回读结果，选中商品和请求数量保持稳定。未改动共享布局来规避截图行为，也未把跨手机/桌面断点保存查询状态列为本页已实现能力。
