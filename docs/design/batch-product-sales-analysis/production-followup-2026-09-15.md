# 批量货号销量：生产验收后的补充修复

## 触发与修复范围

2026-09-15，PR [#168](https://github.com/SeanPPP/hb-platform/pull/168) 合并提交 `c2fc43c9f8217569f747eb673b011c995904c924` 发布后，使用已登录生产账号的实际授权范围验收。首屏已消除逐商品详情请求链，但发现两项需要继续修复的问题：

1. 点击单品仍等待折扣快照，实际一次请求为 20,693.7 ms。销量与金额已经可以从日统计读取，需要让它们独立返回。
2. 全部商品详情 CSV 一次请求返回 HTTP 500。对应服务器日志确认 SQL Server 错误 1205：导出读取折扣快照时成为死锁牺牲者。

补充变更仅涉及批量货号销量页面及其服务和测试，不更改统计表、索引、后台任务或其他报表。

## 接口与行为

- `/detail` 新增 `includeDiscounts`，默认 `true`，保持旧客户端行为。新页面传 `false`，可靠销量、金额、每日数据及分店合计独立返回。
- 页面针对选中单品独立调用已有 `/overview/discounts`，只合入范围、日期和覆盖版本一致的分类字段；不会用全商品分类覆盖单品结果，也不会覆盖可靠销量。
- 分类未知、在途、失败保留原有未知值。选择变化、刷新、会话变化时取消旧请求，丢弃晚到结果；沿用 409 和 401/403 的处理规则。
- 导出只对每批折扣快照读取遇到的 SQL 1205 增加最多两次重试，短暂等待支持取消。其他异常直接传播，重试耗尽继续失败，最终权限和日期版本校验保持。

## 生产样本及数据口径

查询日期为 2026-08-17 至 2026-09-15，10 个商品、58 家实际授权分店。商品货号为 HB053-074、075、076、077 及 HB053-XM-001、002、005、007、008、009。当前 30 天均已完成统计；用户最初截图中的未完成日期在验收时已经补齐。

生产日统计表只读核验确认，这 10 个货号对应的商品，在接口回传的 58 家分店及 30 天日期集合中均无事实记录，数量和金额合计均为零。因此本次生产页面的零销量不能用来证明有销售数据的聚合正确性；非零、退货和部分日期场景另由隔离 SQL 与前端专项测试验证。

首轮生产观测为公网浏览器单次或少量请求，不能作为 P95：首屏 query 4,266.2 ms，随后三次刷新分别为 290.1、1,564.0、1,233.6 ms；单品详情 20,693.7 ms；分店首次 4,496.8 ms，后续未缓存样本 290.6、287.5 ms。后台折扣仍有独立等待。尚无证据把其耗时归因于缺少索引、纯 SQL 执行或 JSON 解析。

后端新增 5 项隔离 SQL 测试均通过：两次死锁后成功、死锁耗尽、非死锁不重试、观察到第一次快照 SELECT 后在退避期间取消，以及快速单品详情不读取快照且分类保持未知。1205 错误通过真实查询执行回调注入，未在生产制造死锁。Release 构建为 0 警告、0 错误。前端专项测试及类型检查通过。独立 code-reviewer 已确认后端及两份精确发布脚本无未解决 P1/P2；前端动态回归和独立审查仍在进行，补充发布结果另行记录。首次发布的后端源码、旧镜像和静态文件备份均已保留。原始生产请求、只读统计核验、布局截图及发布清单位于本隔离工作区的 `apps/web/tmp/batch-sales-performance/`，不加入发布包。
