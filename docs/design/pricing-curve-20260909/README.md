# 自动定价曲线与尾数防倒挂

## 业务规则

横轴为进货成本，纵轴为建议零售价。在同一有效策略的覆盖范围内，成本增加时理论售价和最终售价均不下降；理论成率不增加，尾数调整后的实际成率允许局部回升但始终在 1.5～5。人工售价、促销折扣和不同供应商/分店之间的不同策略不作跨策略价格排序。

现有 Linear 直接升级为零售价线性插值。ArcUp/ArcDown 是可调整弧度的二次曲线。Step/Exponential 保留旧算法，不提供未经校验的跨区间单调保证。策略选择沿用 #105 的供应商与分店联合范围规则。

图形节点代表最终售价，吸附到 .50/.99 或特殊整数 1、2；成本通过数字输入修改。节点价格以两位小数独立保存，避免四位成率无法恢复精确售价。拖拽仅纵向移动；各段独立选择形状、通过安全弧度滑块调整。增加和删除节点只将相邻段重置为直线。旧策略打开时不自动转换图形节点；已有 Linear 的计算升级不依赖转换按钮。

## 计算与精度

对于节点 (a, Pa)、(b, Pb)，h=b-a、D=Pb-Pa、t=(x-a)/h：

```
P(x) = Pa + D*t + B*t*(1-t)
B = D*CurveBend
C = a*Pb - b*Pa
max(-D,C/b) <= B <= min(D,-C/a)
```

节点成率须在 1.5～5 且不增加，售价须不下降；相邻区间共享同一成本和售价节点。对旧零成本起点可使用等价的端点导数校验，运行时仅接受实际成本至少 0.10。

尾数计算先沿用当前 .50/.99 分档（合法尾数本身固定），再在合法价格集合内夹到 `[1.5*x,5*x]`：下界取最小合法尾数，上界取最大合法尾数。不能直接把普通数字截到上下界，否则会破坏尾数。不到 0.10 的成本不能满足最低合法售价 0.50 与成率上限，计算返回明确错误。

CurveBend 保存前向零截断六位小数，StartRate/EndRate 按四位小数规范化，再进行验证。前端不在尾数判断前把理论价保留两位小数，只消除阈值附近的机器浮点误差。后端 decimal 计算是最终依据。

原 CalculateRate 返回理论成率；试算响应额外包含 EffectiveRate，最终展示成率由最终售价除以成本得到。指定策略域外计算明确拒绝；未命中任何策略的历史默认行为保留，不应将它理解为已通过曲线校验。

## 兼容与发布

新增迁移 `20260909.001-pricing-curve`，只在 `dbo.PricingStrategyDetail` 增加三个可空字段：StartRetailPrice decimal(18,2)、EndRetailPrice decimal(18,2)、CurveBend decimal(18,6)。旧行不回填、不删除。列存在时校验精确签名，不覆盖错误结构；正常应用启动只读检查迁移账本和列签名。

部署前必须导出备份现有定价策略、明细、目标和当前可运行版本，并检查启用策略。旧 Linear 的不连续成本区间、不一致交界售价、越界倍率等会被新运行时拒绝，不能假设所有历史配置均兼容。先根据业务要求修正并试算，不应自动改价或批量重定价历史商品。

按照项目部署 runbook 在目标环境运行新版本 `--schema=migrate`，随后 `--schema=check`；检查成功后才能启动新应用。发布后验证真实策略保存回读、试算和商品维护/进货单预览的一致性。本 PR 合并不代表上述生产迁移、部署或业务验收完成。

回滚保留新增可空列即可，但若发布后已保存 ArcUp/ArcDown 或精确端点策略，需要同时恢复发布前的策略配置备份；旧应用不理解弧线与精确价格字段，不能只回滚二进制后沿用新配置。

## 验证范围

自动化测试覆盖 1～999 每 0.01 成本点扫描、有效/无效上下弧、尾数固定点和成率上下界、15→20 成本反例、浮点阈值误差、六位弧度保存回读、数据库写入失败事务回滚以及迁移账本/只读检查。真实 SQL Server 用例只接受专用测试连接 `HBWEB_SCHEMA_SQLSERVER_TEST_CONNECTION`，缺失时明确跳过，不读取生产凭据。
