# 分时营业额同期数据缺失修复（HBSales 历史窗口）

**现象：** 移动端「分时营业额」同期（2025 年）各小时为 0，而门店汇总同期正常。

## 根因

- `StoreSalesStatistic` 在 HBSales 历史窗口内叠加 HBSales；`HourlySalesStatistic` 的两份生成实现只聚合 POSM。
- 分时完整性核验只用 POSM 覆盖判断「哪些分店应有数据」，只在 HBSales 有单据的分店被视为不该有数据，缺口永远不会触发补算。
- 查看同比报表会触发 POSM-only 重算，重算先删整天分时行再插入，把早年一次性导入的 HBSales 小时数据抹掉。生产只读核验：2025-07 至 09 的缺口日期，分时表更新时间都恰好是一年后同一天。

## 生产只读核验（2026-09-17，43.159.37.55 备份库）

| 项目 | 结果 |
|---|---|
| 2025-09-18 分店 1012 | 分店日统计 8053.28 / 509 单 = HBSales；POSM 0；分时表无行 |
| HBSales 最后一笔结账 | 2026-04-12（2026-01 至 04 仅 1023、1012 零星单据） |
| 并存期 2025-10 至 12 | 165 个「日期 + 分店」两来源都有单据，属逐台收银机切换，口径相加 |
| 分时表 OrderCount | 2025-12 至 2026-05 全为 NULL，首次查看会触发重算，属既有状态 |

## 改动

1. `SalesStatisticsHBSalesHistoryWindow.EndExclusive` 后移到 2026-05-01。
2. 新增 `SalesStatisticsHourlyRefresher`，业务切片与完整刷新编排器共用；历史窗口内叠加 `LoadHBSalesHourlyAggregatesAsync`。
3. 分时完整性核验改用 POSM 与 HBSales 并集覆盖。
4. 既有「2026 即窗口外」用例日期改到 6 月；新增窗口边界、双来源相加、指定小时、窗口外不读 HBSales、报表同期补算用例。

## 部署后回填

入口：`StatisticsJobTriggerController.BatchUpdateHourlyStatistics`，按月分段夜间执行。

1. 2025-09 至 2025-12（今年剩余月份同比立刻用到，含并存期）。
2. 2025-01 至 2025-08。
3. 2024-09 至 2024-12。
4. 可选：2026-01 至 2026-04，使分店 1023 的零星 HBSales 单据进入分时表；分店日统计对应日期也可顺带重算。

每段跑完在「统计对齐」页面核对小时统计与分店统计基线一致。
