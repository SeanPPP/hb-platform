# iPad 收银：手动刷卡与礼品卡

## 目标与交互

沿用现有 iPad 收银布局、颜色与触控组件，对齐 WPF 的支付入口和保存设置习惯。

| 设置 | 默认值 | 收银页行为 |
| --- | --- | --- |
| 手动刷卡 | 关闭 | 开启后显示手动刷卡，隐藏集成信用卡；关闭后恢复原 Square/Linkly 选择 |
| 礼品卡支付 | 关闭 | 开启后显示礼品卡，沿用现有 voucher 查询、锁定、核销与恢复流程 |

设置页编辑草稿，点击保存后生效；原刷卡机配置单独保留。保存需要支付设置权限，且没有活动购物车或待处理交易。保存与交易共用独占保护，耐久写入成功后同步发布内存设置快照，即时生效，无需重启应用。

手动刷卡流程：选择入口 → 显示剩余应付全额（只读）→ 收银员在外部机具操作 → 勾选已确认付款成功 → 确认并保存。关闭、切换方式或金额变化都清除本次确认。普通销售可用；分期和退款不开放手动刷卡。

## 交易与恢复约束

- 手动刷卡不调用 Linkly 或 Square。服务端同步保留 Manual 处理器和 MANUAL 引用。
- 人工确认先绑定到同一耐久支付动作；确认后的保存失败仅恢复原动作，不创建新收款。
- 已有 Unknown、未完成核销、订单提交或回执确认继续阻塞新交易。
- 关闭入口只影响新付款，已存在的支付恢复仍可取得原适配器。
- 礼品卡沿用现有服务端礼券业务，不新增充值或直接发卡功能。

## 分工与验证

1. 设置子代理：独立本地设置仓库、设置页草稿/保存、中英文和测试。
2. 支付数据子代理：manual-card 适配器、确认记录、支付账本/同步映射及共用类型兼容测试。
3. 支付 UI 子代理：入口、只读金额、人工确认、presenter 校验和交互测试。
4. 主代理：生产环境组合、设置保存权限和并发保护、运行时校验、整合检查。

验收覆盖：默认关闭、卡方式互斥、礼品卡显隐、缺少确认拒绝、重复点击、持久化失败恢复、关闭开关后的旧交易恢复、权限变化、分期/退款隔离。执行 TypeScript 检查、对应单元/组件测试、共享边界检查；Windows 环境无法替代 iPad 真机和 Xcode 原生安装验证。
