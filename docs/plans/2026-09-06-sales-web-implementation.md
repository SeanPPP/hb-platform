# 销售明细与营业额正式 Web 落地

## 目标与边界

将已确认的简洁报表设计落到两个现有路由，复用移动端报表的日统计、完整快照和权限校验。目标为进入页面或更改筛选后 3 秒内显示首批真实数据；分别记录 API、首批渲染、整页就绪，不能用演示数据或骨架屏作为达标证据。

本轮只改本地 Web/相关只读后端接口及测试，不提交、不部署、不修改数据库配置或重建统计。保留工作区已有移动端版本管理等改动。

## 设计与交互

- 销售明细：澳洲 / HB 仓库国内双标签；左供应商、中分店、右商品，名称固定、栏内滚动、单栏展开和调整宽度。
- 三维独立筛选与反查，各候选不受自身选中项收窄；关键词在后端全量过滤，商品分页；逐项清除、清除全部。
- 移动端字段：销售额、客单数、客单价、毛利额、毛利率、数量/均价/占比，当前/同期上下显示。null 成本与真实零毛利必须区分；不对商品或供应商客单数直接求和冒充去重交易数。
- 营业额：汇总、分店排名、小时趋势、周/分店/日层级联动，选择分店可转到同日期销售明细。
- 日期快捷键使用当前日期计算，当前周/月截止今天。页面隐藏停止请求，日期/筛选变更取消旧请求，失败不能继续把旧范围数据显示成当前结果。

## 实施顺序

1. 核对移动端 endpoint/DTO/统计口径与页面缺口；图工具不可用时用限定源码调用链核对影响。
2. 添加 Web 报表共用日期、请求生命周期与性能测量；测试日期边界、取消、陈旧回包、缓存和 null 毛利。
3. 补最小只读后端联动契约，复用现有完整快照与统计聚合，覆盖权限/产品反查/筛选/分页/成本和并发。
4. 正式实现销售明细三栏、真实字段与两类供应商联动。
5. 独立实现营业额页，使用已有移动端营业额接口、渐进显示与可点击钻取。
6. 类型检查、构建、专项测试；浏览器验证桌面/窄屏、日期/反查/关键字/毛利/错误状态；记录 API 和 UI 的 3 秒验收证据。

## 验收限制

尚未部署的新后端无法在生产获得真实端到端计时；如本地缺少已授权数据连接或登录态，需要明确报告未验证项，不擅自扩大部署/凭据权限。

## 本轮执行结果

步骤 1–5 已完成，步骤 6 的本地部分已完成：后端组合回归 374/374、前端 7 组专项脚本、Web 类型检查及开发模式构建通过。浏览器已验证三维反查、关键字/IME、毛利缺失、异常独立重试、旧请求取消、日期/同比、周层级与跨页联动、桌面/窄屏布局；两页正式组件截图及可点击演示见 [落地验收记录](../design/sales-reports-web-implementation/README.md)。

生产性能验收仍未完成。旧同源接口本轮首次观测约 4.32–4.85 秒，同查询再次读取约 0.31–0.51 秒；均不能证明新接口达到 3 秒。需获准部署后继续测量，未提交、未推送、未部署，未修改生产统计策略或数据库。
