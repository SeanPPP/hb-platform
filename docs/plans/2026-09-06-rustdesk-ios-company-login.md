# RustDesk iOS 公司账号与设备列表实施计划

**目标：** 官方 RustDesk iOS 配置公司 API 后，用现有 HBWeb 系统管理员账号登录，自动显示受管公司设备，并显示 RustDesk 在线状态。

**方案：** 在现有主 API 内增加 RustDesk 客户端兼容接口，继续使用当前 hbbs/hbbr。客户端只获得用途受限的专用会话；不向 RustDesk 返回通用 HBWeb 管理 JWT。设备列表汇总仍有效的已登记 Windows POS 和显式纳管的 Mac。

**约束：** 不恢复已移除的独立通讯录容器；不修改或公开已有账号密码；不向通讯录批量下发无人值守密码；不自动纳管任意 hbbs 注册者；不更改现有 POS 自动更新策略。保留旧镜像、数据、密钥和源码回退路径。GitHub 公开推送仍需单独授权。

- [x] 核对官方 RustDesk 1.4.9 的登录、用户资料、通讯录、新旧协议回退及在线状态链路。
- [x] 复用公司密码验证及账号状态/角色检查，新增专用会话、限流、退出与过期；验证专用 token 无法调用普通 HBWeb 管理接口。
- [x] 实现公司共享设备列表：现有 Windows POS 每次核对最新有效登记；Mac 通过管理员显式登记。仅同步设备 ID、名称、平台等必要信息，不同步密码。
- [x] 新增显式 schema 命令和只读门禁，限定新会话/受管设备表及索引；使用生产兼容 SQL Server 验证。
- [x] 按官方协议增加认证和通讯录 HTTP 测试，覆盖普通用户/禁用账号/过期会话/退出/越权/输入边界/未知设备等；完成独立安全审查。

- [ ] 使用官方 Mac 客户端核验同一协议的登录、公司通讯录和在线状态，再引导 iOS 填写 API 地址完成实机验收。需要用户输入管理员密码时保持同一应用上下文交接。
