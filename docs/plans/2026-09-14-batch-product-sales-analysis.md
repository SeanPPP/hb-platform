# 批量货号销量分析解耦实施计划

**目标：** 在 HB Web 增加可到达的批量货号销量页，按用户选择的第 1 张设计图实现导入、商品选择、每日趋势、分店销量和折扣识别。

**方案：** 新增独立查询服务及三栏页面，通过单独 TypeScript/C# 契约衔接；共享路由、权限、国际化和依赖注入只由主代理修改。

**约束：** 工作树 `/Users/sean/.codex/worktrees/hb-batch-product-sales-20260914`，分支 `codex/batch-product-sales-20260914`，基线 `4e3918913`。原工作区脏文件保持原样。新增分析查询 API；历史统计缺失时通过既有持久队列生成派生统计，不修改商品或交易。当前仅本地实现和隔离测试，未迁移或部署生产。实现子代理按用户要求使用 `gpt-5.6-terra`。

## 视觉目标与业务口径

- 第 1 张图：`/Users/sean/.codex/generated_images/01a09d94-abff-7c10-ae7a-452e75903766/exec-c48dc809-0381-42d1-9bdc-f1c74e759a5c.png`。
- 左栏：粘贴/Excel 导入、去重/匹配状态和商品列表；中栏：当前商品、每日正价/折扣图和日明细；右栏：分店表、选中分店的每日图。
- 真实商品图复用 ProductFlowShared/ProductImage，图表使用现有 React/SVG 图表模式，图标复用 Ant Design。
- 货号精确按文本匹配，保留前导零；多商品映射标为歧义，不自行取第一条。首版支持 `.xlsx` 和 `.csv`，旧 `.xls` 明确提示另存格式。
- 净销量包含退货。正价、折扣、未知各类为有符号净数量，合计等于 quantity；returnQuantity 只作正数退货量辅助展示，不再次扣减。
- 折扣以成交时原价/折扣记录判断，不能用当前商品价或平均价倒推。无法判定的数据明确显示未知；只有数值非负且无未知量时展示占比。
- 全部分店表示当前账号允许的门店；日期首尾包含，最多 366 天、500 个货号。摘要与明细不同来源的差异必须显式报告，不静默替换。

## 独立契约

`apps/web/src/types/batchProductSalesAnalysis.ts` 为前端契约。新增 API 根路径 `/api/react/v1/dashboard/batch-product-sales-analysis`：

1. `GET /options`：可见分店和上限。
2. `POST /query`：批量货号匹配、商品摘要、查询范围和统计完整性。
3. `POST /detail`：单商品同范围的日/分店/分店日拆分，避免逐门店 N+1。

后端采用现有 ApiResponse 包络，客户端解包后提供 `BatchProductSalesApi`。前端只在用户查询时应用筛选快照；商品切换取消过期明细请求，旧结果不能覆盖新选择。

## 权限与统计就绪行为

- 独立权限 `SalesDashboard.BatchProductSales.View` 同时控制前端路由、菜单、角色预览、后台入口和三个 API。每次 API 请求重新核对实时精确权限，旧 JWT 不能绕过权限撤销。
- 普通用户只读当前可管理门店，全店角色取实时快照；请求门店不得越出实际有效范围。
- 缺失统计只对非 Fresh 日期提交既有持久队列；2025 采用年度回填通道，其他年份每批不超过 31 天，重复查询由队列幂等去重。等待/提交失败时不显示虚构的零销量。
- 每个原始源命令有 60 秒超时，并通过独立 SqlConnection/DbCommand 真实传递取消；全年多店生产规模性能须上线前实测。
